# OMF2115 move catalog

Generated by `project/prototype/generate_move_catalog.py` from the local animation inventory,
`pose_catalog.csv`, the recorded source traces and `move_names.csv`. Do not edit by hand;
add names to `move_names.csv` and regenerate.

**Status.** *authored*: every sprite has a pose in `pose_catalog.csv`. *partial*: some do.
*generic*: the viewer shows only the shared rough pose, so the move barely reads.
**Trace** is a recorded fight containing the move (`--source-replay`); *none* means it can
only be seen by performing it in a live fight. Input directions are numpad digits
(4 back, 6 forward, 2 down, 8 up).

## Seeing a move

- **Browser:** `python project/tools/generate_move_browser.py` builds `project/build/move-browser/index.html`, which lines up each original sprite with the blockout and Meshy renders of the same frame (moves that appear in a trace only).
- **Original sprites:** `python project/tools/pose_inventory.py --har H --animation N --export-sprites` writes `project/build/pose-reference/<har>/N/sprite-NN.png`.
- **Blockout vs Meshy, from a trace:** run the replay command above once normally and once with `OMF3K_MESHY=1`.
- **Live:** `project/scripts/run-live.ps1` for blockouts, `run-meshy-fight-jaguar.ps1` and `run-meshy-fight-shadow.ps1` for the Meshy models.
